Glass-Box, explained

Inspect a language model, form a hypothesis, make a targeted activation edit, then freeze the comparison into an auditable study.

Glass-Box supplies the instruments. The study framework supplies protocols, sessions, execution, receipts and reports. Start with a synthetic example before connecting a model.

Software workflow, not a discovered model circuit. The current study runner automates fixed likelihood-scoring trials, not automatic hypothesis search.

How the software pieces connect

Study → runner → session/backend → receipts → report

A local backend owns a lazily loaded model. A remote backend sends the same JSON operations to an existing worker. Reports read saved evidence without loading weights.

Protocol fingerprints reject changed studies on resume. Source/runtime identity prevents silently mixing implementations. Budgets count starts and failures; a time limit prevents new calls but does not cancel an in-flight operation. Interrupted attempts are charged and not silently retried.

A midpoint edit changes both the MLP input and its skip path

The initial adapter targets one pinned LFM3-1.7B instruct model. Each of its 24 blocks has an attention or convolution operator and an MLP, a feed-forward transformation.

One address system

L2.h0 · attention head
176 heads across 6 global- and 5 sliding-attention blocks. Gate clamping and output scaling are different operations.
L0.c0 · convolution channel
26,624 channels across 13 conv blocks. Seven kernel taps describe lags 0–6, not seven editable channels.
L0.n0 · MLP neuron
184,320 neurons across 24 MLPs. Mean scaling needs an explicit calibrated mean.
L12.res.mid · residual checkpoint
72 in/mid/out names describe 49 physical checkpoints. One block's output is the next block's input.

Counts: pinned adapter's layer layout and coordinate bounds. Architecture counts are not inference results from this extraction.

Unit names a site. PatchSpec describes an edit. GlassboxHooks applies it temporarily and removes hooks on exit, including exceptions. It changes activations, not trained weights.

A clean-state donor must have the same token count as the receiver. Matching is by absolute position, not meaning. Clean-source donors work for score and probe, not generate.

Native and frozen normalization are different conditions

Native normalization is the default. Frozen mode fixes only post-operator and post-FFN RMS denominators from an unpatched pass on the same receiver input. It does not freeze final normalization or use donor denominators. Frozen mode is engineered and needs its own identity control.

Five calls answer different questions

probe · what is active?
Internal readings, projections and optional source-token routing. A high projection is not proof that a unit is necessary.
attribute · what is locally sensitive?
Activation × gradient for a fixed target-minus-foil logit margin. Local sensitivity does not predict every consequence of a large edit.
sweep · what changes under ablation?
Finite zero edits to selected heads, operators, MLPs or blocks. Signed deltas are condition-specific intervention effects.
score · how does fixed likelihood change?
A token margin, token log probability or supplied-continuation log probability. Teacher forcing scores text you supply, not text the model chooses.
generate · what tokens does it choose?
Greedy cached continuation with telemetry replay. This alone is not a benchmark or correctness harness.

A likelihood change is not an answer-quality result. It does not establish generated correctness, a native circuit or practical benefit. Those need their own fixed tests and evidence.

Try the full study path without weights

After installing the local package with Python 3.12, export the two unrun protocols and their synthetic walkthrough. The same commands work outside the source checkout.

glass-box examples --output ./my-studies
glass-box validate ./my-studies/code_retrieval.json
python3.12 ./my-studies/fake_walkthrough.py --output ./synthetic-demo --summary
glass-box report ./synthetic-demo/code-retrieval-mechanics-v2
python3.12 ./my-studies/audit_controls.py ./synthetic-demo/code-retrieval-mechanics-v2 --tolerance 0.000001

The walkthrough uses invented arithmetic and token IDs. It runs discovery and validation, resumes without new scores, builds reports and closes the session. The output retains protocol, journal, raw receipts and JSON/Markdown reports. Without --output, temporary receipts are discarded. The summary counts direct smoke scores separately from budgeted trials. It tests software plumbing, not LFM3 behavior.

The identity audit checks declared pairs against the explicit fixture tolerance without rescoring. It is not a correctness test. Protocol validation checks schema only, not tokenization or model readiness. See the real-model preflight checklist.
